## Goal

The mod's source lives in a public GitHub repo, `expectbugs/freelancer-carrier-mod`, under AGPL-3.0. A machine-enforced gate makes it impossible to commit or push Freelancer/HDE game files or extracts, decompiled code, other mods' content, `local/` research, secrets, or Adam's personal infrastructure details. One CI entry point, `harness/ci.sh`, exists that every later package extends. The repo is public because Adam asked for it (AUTONOMY §1). The gate exists because a single leaked game file or personal detail cannot be taken back.

- **REQ-P0-REPO-4:** `tools/check_public.py` (stdlib-only Python 3.11+, run with `python3 -I`) has three modes. It exits non-zero with a per-file reason if any rule fails.
  - `--staged`: the files in the index.
  - `--tree <path>`: if `<path>` is a git work tree, the file list comes **only** from `git -C <path> ls-files -co --exclude-standard`. Never walk the directory, so `local/`, `vendor/`, `.venv/` and `build/` are never scanned. `.claude/` is always skipped (agent worktrees live there).
  - `--release <dir>`: vets a directory of release assets. It is source-only by default. Built `.dll` files are allowed only with `--allow-binaries`, which the release step passes only after W5-SHIP has verified FLSDK redistribution licensing (CONVENTIONS §11).

  The rules:
  1. **Forbidden extensions anywhere:** `.cmp .3db .mat .txm .utf .ale .vms .thn .sph .sur .wav .mp3 .ogg .bini .fl .exe .dll .lib .pdb .dmp .mdmp`, image files over 512 KB, and any file over 5 MB.
     - **Allowlist:** `.png` and `.jpg` under `docs/` up to 512 KB, and only if not a game texture. The checker cannot know this, so it requires a sibling `<name>.source` text file stating "generated by …" or "own work".
  2. **`.ini` files** are only allowed under `harness/config/`, `sidecar/config/`, `toolchain/` and `tests/fixtures-authored/`. Even there, a file is rejected if it contains more than 20 lines matching Freelancer data section headers (`^\[(Ship|Solar|Base|Room|Zone|Object|Good|MarketGood|Loadout|NPCShipArch|EncounterParameters|Pilot|Faction|Group|system)\]`, case-insensitive). Generated overlays live in `build/` and `out/` and are gitignored.
  3. **Path rules:** reject anything under `local/`, `build/`, `out/`, `vendor/`, `refs/` or `.venv/`, or any `*.carrier.json` save sidecar.
  4. **Content rules** (any text file). **This public spec deliberately contains no personal literals.**
     - **Personal literals** (Adam's email, LAN/Tailscale/VPN IPs, device serials, account labels) come from the **local blocklist** `/home/user/freelancer/carrier-mod/local/public_blocklist.txt`: gitignored, one literal per line, `#` comments, matched case-insensitively. The orchestrator created it. If it is missing (e.g. a fresh clone elsewhere), the checker warns and continues with the generic rules only. Never copy its contents into any committed file, test fixture or log.
     - **Generic regexes:**
       - CGNAT/Tailscale `100\.(6[4-9]|[7-9]\d|1[01]\d|12[0-7])\.\d+\.\d+`;
       - RFC1918 private ranges `10\.\d+\.\d+\.\d+`, `192\.168\.\d+\.\d+`, `172\.(1[6-9]|2\d|3[01])\.\d+\.\d+`;
       - any email address **not** ending in `@users.noreply.github.com` or `@anthropic.com`. Commit-trailer `noreply@anthropic.com` is allowed. Allow `example.com`/`example.org` placeholders.
       - Exempt `127.0.0.1` and documentation-only `0.0.0.0`.
       - Unit tests use synthetic values like `10.1.2.3` and `someone@example.net`, never real ones.
       - **Allowlisted synthetic literals.** `10.1.2.3`, `192.168.1.77` and `someone@example.net` are always allowed, because this spec and the tests cite them. Without that, `--tree .` would flag this very file.
     - the strings `PHONE_IP`, `PHONE_PORT`, `api_key`, `ANTHROPIC_API_KEY=`, `sk-ant-`, `ghp_`, `gho_`, `BEGIN .*PRIVATE KEY`;
     - references to `~/aria`, `/home/user/aria`, `aria2`, `G2CC`, `rt-zomboid` outside `docs/plan/` (the plan may name them as forbidden imports);
     - the decompilation marker `Freelancer-Decomp` inside `src/` or `sidecar/` code files. Citing it is allowed in `docs/`.
  5. **Bulk game text:** reject a file containing more than 3 runs of 8+ consecutive lines that look like FL INI `key = value` data whose keys are in a fingerprint set (`nickname`, `ids_name`, `ids_info`, `DA_archetype`, `material_library`, `hit_pts`, `loadout`, `archetype`, `pos`, `rotate`, `shape`, `encounter`, `faction`, `density`). This catches pasted INI blocks in Markdown or YAML; YAML data we author uses different key names (snake_case).
  - Exit codes: 0 = clean, 1 = violations, 2 = usage error. `--explain` prints each rule.

## Pitfalls

- Pushing anything once is permanent in practice (forks and caches). Run the checker **before** the first push.
- Don't commit `local/`. It contains research with personal-infrastructure notes (R6) and derived game data (R3-data).
- Never use `gh repo create --push` or `--source .` from your worktree: it would publish the unreviewed `wp/P0-REPO` branch.
- The public-safety workflow must not need secrets or the game.
